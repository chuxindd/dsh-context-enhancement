## 1. 目标与实现设计

### 1.1 注入预算 I 的单一配置与解析来源
- 明确区分 byte 预算与 token 预算：原 prompt 配置中的 `maxBytes` 属于渲染字节上限，不可假装成 token；
- 新增 `maxTokens?: number`，默认回退至 `DEFAULT_TASK_STATE_INJECTION_BUDGET_TOKENS = 512`；
- 提供单一解析入口 `resolveInjectionBudget(config: TaskStatePromptConfig): ResolvedInjectionBudget`，将 `maxBytes` 与 `maxTokens` 统一规整为安全正整数；
- Token 定价函数 `estimateSlotTokens(text, meter?)`：优先通过真实 `meter.estimateMessage` 计价；在缺少 tokenMeter service 时采用保守 fallback 计价，准确感知 CJK 字符（每字 1 token）与消息结构化开销（Role 4 + Text block 4），严禁单纯使用 `chars / 4` 假冒。

### 1.2 优先级截断与权威最小表示 fail-closed
- 严格遵循权威优先顺序：
  1. Authoritative Goal view 与 Authoritative TODO view；
  2. Continuation state（currentObjective、currentFocus、openWork、nextActions）；
  3. Constraints / Risks / Decisions / Facts；
  4. Evidence references。
- 截断按行自底向上剥离低优先级列表，保留权威视图；
- 若权威最小表示（Header + Staleness + Goal + TODO）连同截断标记 `TASK_STATE_TRUNCATION_MARKER` 仍超过 `maxBytes` 或 token 预算 `I`，执行 **typed fail-closed (blocked)**：返回空文本与 `staleness: 'blocked'`，不向模型注入误导性半截 Goal/TODO。

### 1.3 Staleness 标记与动态 fresh/stale 状态转换
- 扫描 Session 日志中非 slot 节点的最高 projectable eligible 序号，得到 `eligibleHighWater`；
- 当 `eligibleHighWater > stable.sourceCursor` 时，在文本中显示明确的 `TASK_STATE_STALE_MARKER`，并在 metadata 中记录 `staleness: 'stale'`；
- 当后续 catch-up revision 提交使得 `stable.sourceCursor >= eligibleHighWater` 时，自动移除 marker 并恢复 `staleness: 'fresh'`；
- 扫描时明确排除 `task-state-slot` 节点自身，杜绝 slot 自反馈。

### 1.4 Source Metadata 与 Diagnostics 扩充
- 在 `TaskStateSlotSource` 与 `TaskStateSlotRecord` / `TaskStateSlotDiagnostics` 中补齐字段：
  - `eligibleHighWater: number`
  - `staleness: TaskStateStaleness` ('fresh' | 'stale' | 'blocked')
  - `injectionTokens: number`
  - `budgetTokens: number`
  - `truncation: boolean`

### 1.5 Compaction 安全预算 G 扣除与 Ledger 对账
- 严格遵循理想化落地方案公式：`G = max(0, W - E - R - M - I)`；
- 在 `resolveEnvelopeBudget` 与 `resolveEnvelopeZoneBudget` 中增加 `injectionTokens?: number`：
  - `surfaceGrantTokens = max(0, contextWindow - envelopeTokens - responseReserveTokens - safetyMarginTokens - injectionTokens)`
  - `waterlineGrantTokens = max(0, forgetWatermarkTokens - envelopeTokens - injectionTokens)`
  - `envelopeDominated = envelopeTokens + injectionTokens + retainedTailTokens >= pressureTokens`
- 在 `BasicCompactionEngine` 中：
  - 通过 `visibleSlotTokens(session, measurement)` 从当前 surface 节点及 tokenMeter 测量中直接归属 slot 实际 injection tokens；
  - 在 `pressureLedger` 与 `inspectLedger` 中记录 `injectionTokens` 与 `usageBaseline`（支持 provider usage 存在与缺失两条对账路径）；
  - 避免 slot tokens 被同时算作非 surface 信封导致的“双扣”。
