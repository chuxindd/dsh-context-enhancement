## 1. 前置：DSH surface replacement 契约复核（未修改 checkout）

checkout `C:\Users\chuxi\Documents\trae_projects\code\deepseek-harness`，HEAD `a66e4702047846cdaa10c66c9d3df3951f5ea70d`，`git status --porcelain` **空**（本批次自始至终未修改该 checkout）。

复核结论（决定了 provenance 只能搭载何处）：

1. **不能挂在 replacement 自身 `data` 上。** `assertToolResultRewrite`（`packages/core/session/src/surface.ts`）要求 `tool/result` surface replacement 除 `message.content[0].content` 之外**每个 `data` 键都必须与遮蔽原节点深度相等**，`message` 的 `source`/`turn`/`step` 也必须一致；附加 provenance 字段会被判为 "may change only content" 而拒绝。
2. **不能新增插件自有 Session 事件类型。** `Session.append(type, data, ...)` 无 `ignorable` 选项，而持久化读取路径 `assertEventsSupported`/`KNOWN_SESSION_EVENT_TYPES`（由 harness 自身词表生成）拒绝不在该集合内且未标 `ignorable` 的事件类型。新事件类型会让**所有被本插件写过的 Session 在重启后整体不可读**——比原缺陷更严重，直接排除。
3. **不能对 `compaction/prune` 做 module augmentation。** 该 data 为封闭 interface 成员；实测（临时探针 + `tsc`）得到 `TS2717: Subsequent property declarations must have the same type. Property ''compaction/prune'' …`。因此附加字段由**写入侧自有拓宽类型**承载，读取侧从日志 JSON **逐字段重新校验**。
4. **`compaction/prune` 是唯一可行载体。** 它本就是本包两条归约路径共享的 shadow-price 协议事件，且由写入方**同步紧邻**落在 replacement 之前（该相邻性是记录的可寻址位置）。`compaction/prune` 的 data 在 `session-persistence-jsonl` 中按 JSON 原样往返（无逐类型 data 校验），官方 compaction invariant 只校验已知字段，故附加字段运行时安全。

## 2. 实现设计

### 2.1 provenance 记录（`ReductionProvenance`）

| 字段 | 含义 | 校验（读取期，任一不满足即 fail closed） |
| --- | --- | --- |
| `producer` | 固定 `'dsh-context-enhancement'` | 必须严格相等 |
| `schemaVersion` | 固定 `1` | 必须严格相等 |
| `kind` | `'tool-summary'`（语义工具组摘要）｜`'tool-pruned'`（模型无关确定性裁剪） | 必须是这两个字面量之一 |
| `coveredSeqs` | 本 replacement 现在代表的 surface 节点 | 必须与**官方** `shadowedSeqs` 逐元素同序相等；非空 |
| `sourceEventSeqs` | 归约所依据的全部 Session 事件（summary = 整组事件范围；prune = 被遮蔽该节点） | 非空、去重、每个 seq 严格早于 replacement.seq；必须**包含** `coveredSeqs` |
| `groupId` | 语义摘要的工具组身份（= 审计调度该组所用同一 fingerprint）；prune 为 `null` | `tool-summary` 必须为非空字符串；`tool-pruned` 必须为 `null`（不得凭空造身份） |
| `generation` | 落盘前观测到的 surface `replaceGeneration` | 非负安全整数，且 `<= session.surface.replaceGeneration` |
| `digest` | 绑定其余全部字段 + replacement 文本 | 必须与读取侧按同一算法重算值相等（64 位小写 hex） |

digest 组成（`reductionDigest`）：`sha256(JSON.stringify([producer, String(version), kind, JSON.stringify(coveredSeqs), JSON.stringify(sourceEventSeqs), JSON.stringify(groupId), String(generation), JSON.stringify(replacement 文本块数组)]))`。
文本块数组只取 `text` 型 block 的 `block.text`（**按文档顺序**递归包含嵌套 `tool-result` 内的文本），故 JSON 往返重排对象键不会改变摘要；用 JSON 数组而非拼接字符串，避免分隔符歧义造成不同文本碰撞。

### 2.2 写入侧（两个真实 producer）

- `src/internal/compaction/tool-group-replacement.ts`（语义摘要，op1）：`kind:'tool-summary'`、`coveredSeqs=[sourceSeq]`、`sourceEventSeqs=[...group.sourceSeqs]`、`groupId=toolGroupIdentity(session, group)`、`generation=session.surface.replaceGeneration`（逐节点读取，故 0,1,… 递增）、`content=message.content`。
- `src/tool-result-pruner.ts`（确定性裁剪，op2）：`kind:'tool-pruned'`、`coveredSeqs=sourceEventSeqs=[seq]`、`groupId:null`、同样逐节点读取 `generation`、`content=已裁剪 message.content`。

两者都通过 `shadowPriceWithProvenance(shadowedSeq, shadowedTokenCount, provenance)` 生成官方载荷 + 附加键，官方三字段（`shadowedRange`/`shadowedSeqs`/`shadowedTokenCount`）语义与校验完全不变。

**工具组身份的一致性保证（未改 `compaction-basic.ts` 的前提下）**：`groupId` 由 `toolGroupIdentity()` 在 writer 内按与 `BasicCompactionEngine.toolGroupFingerprint` **相同输入**重建（lifecycle `{sessionId, createdAt}`、`group.sourceSeqs`、`group.callIds`、事件类型、`contentDigest(events.map(JSON.stringify))`、`schemaVersion:1`）。新测试通过 prototype seam 断言二者**逐字相等**（`records[0].fingerprint === engineGroupFingerprint(session, group)`）。派生而非传入是刻意的：写入方不能采信调用方自造的身份。

### 2.3 读取侧分类（`src/internal/compaction/source-index.ts`）

```
surface node
├─ user/message + task-state slot source ────────────────→ 'task-state-slot'
├─ user/message + plugin checkpoint (replacement) ───────→ 'history-summary'
├─ 非 replacement（裸 append）─────────────────────────→ 'original'
└─ tool/result replacement
   ├─ 校验通过的 provenance ─┬─ 且未被 audit 冲突否决 ──→ provenance.kind
   │                        └─ audit 声称 tool-summary 但 provenance 不是 → 'unknown-replacement'
   └─ 无 / 损坏 / 外来 provenance ──────────────────────→ 'unknown-replacement'
```

- `SurfaceSourceEntry` 新增 `reduction: ReductionProvenance | null`（校验通过的记录；损坏记录读作 `null`，绝不猜类别）。
- `replacementCoverage(seq)`：有校验通过的记录时用其 `coveredSeqs`，否则回退到事件自身 `sourceEventSeqs`（保持既有调用方语义）。
- `buildSurfaceSourceIndex(session, auditClaimedSummarySeqs: Iterable<SessionSeq> = [])`：第二参数语义由“类型权威”改为**诊断性认领**，且**只降不升**——audit 声称某节点是本包已服务的摘要，而该节点持久 provenance 不是 `tool-summary`（含无 provenance）时，两个持久文档互相矛盾，本包**不选边**而 fail closed。`compaction-basic.ts` 的调用点（`buildSurfaceSourceIndex(session, summarized)`）无需改动即成为该冲突围栏。

### 2.4 fail closed 的最小性与有界性

- 失败方向永远指向**保护**：`unknown-replacement` → `isOriginalToolResult=false`（不被再次摘要/裁剪）、`canCompactHistory(..., true)=false`（不被即时重入豁免）、压力规划只能**回避或收窄** span，不会死循环（仍由既有 stop reason 结束本次调用）。
- 官方 shadow-price 定价与折叠**不受影响**：provenance 是附加键，纯消费者（未挂载本包的 DSH）看到的类型与行为完全不变。
