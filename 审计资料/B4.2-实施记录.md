## 1. 被修复的缺陷（单点）

| 编号 | 缺陷 | 修复后的行为 |

| `R-P1-6` | Goal 大幅变化**不会**触发独立 urgent 更新：`goal/change` 与普通进度事件一样只计 1，唯一触发仍是 `pendingEligible >= minEvents`，于是旧 Goal 叙事会被继续注入到下一个阈值窗口 | 任何**改变已提交 Goal 视图**的 `goal/change` 都是 urgent 事实，在 microtask 上请求一波 `urgent`，不等 `minEvents` |

### 3.2 变更要点

- **`contract/types.ts`**：`TaskStateAuthorityStatus = 'current' | 'cleared' | 'none'`；新增 `TaskStateGoalView`（`goalId?/goalRevision?/phase?/objective?`）、`TaskStateTodoViewItem`、`TaskStateTodoView`（`sourceSeq?/items`）；`TaskStateStable` 与 `TaskStateStableContent` 必带 `goalView`/`todoView`/`todoReferences`；`TaskStateContentFields` 组件**只剩** `evidence`（候选不再能写 `todoReferences`）；`TaskStateUpdateTrigger` 增 `'urgent'`。
- **`contract/spec.ts`**：新增三个 view schema，并对"非 current 不得携带值/条目"做 `superRefine`（`cleared` 的 Goal 不得带 identity/phase/objective；`cleared` 的 TODO 不得带 items）；`stableShape` 增 `todoReferences`/`goalView`/`todoView`，`candidateShape` 移除 `todoReferences`。
- **`contract/audit.ts`**：打开行的 `request.trigger` 枚举同步为五值（旧行仍合法：字段可选）。
- **`basic/authority.ts`（新）**：`resolveAuthorityViews(events, base, {maxEntryBytes})`（每视图取窗口内最新事实，无事实则继承 base，再否则 `none`；`changed`/`cleared` 由与 base 的比较得出）、`authorityUrgency(event, base)`、`todoReferencesOf(view, maxEntryBytes)`、`isAuthorityEventType()`、`NO_GOAL_VIEW`/`NO_TODO_VIEW`。
- **`basic/filter.ts`**：`TASK_STATE_FILTER_VERSION` v2 → **v3**；空 `todo/write` 不再返回 `null`，改为 `status: 'cleared'`；非空 write 带 `status: 'current'`；`goal/change` clear 展平 `clearedId`/`clearedRevision`。
- **`basic/types.ts`**：`CandidateHostContext` 增 `authority {goalView, todoView, todoReferences}`；`TaskStateHostNormalization` 增三个 view 字段；`TaskStateReferenceQuarantine.kind` 收窄为 `'evidence'`（TODO 引用不再来自候选，故不再有 TODO 隔离项）。
- **`basic/prompt.ts`**：`TASK_STATE_INPUT_SCHEMA_VERSION` 1 → **2**、`TASK_STATE_STABLE_SCHEMA_VERSION` 1 → **2**；指令删掉 `todoReferences` 输出字段、新增"权威 Goal/TODO 视图"段落（替换/清空/不得复述被取代的 objective/不得复述被清空的条目）；`frameProjection()` 增 `authorityViews`，`contentOfStable()` 增 `goalView`/`todoView`。
- **`basic/host.ts`**：`normalizeCandidate()` 提交 `context.authority`（视图 + 派生引用）而非候选值；删除原"候选 TODO 引用 + 窗口隔离"分支（该字段已不存在于契约）；文档与诊断文案同步。
- **`basic/update.ts`**：`TaskStateUpdateAttempt` 增 `windowEvents`（`worker.performBatch` 传入 `window.events`）；`candidateContext()` 用窗口事件在 **Host 侧**解析权威视图。
- **`basic/worker.ts`**：新增 `maybeScheduleUrgent(seq)`（`urgentThrough` 幂等、`pendingEligible < 1` 早退、`active` 时只登记 follow-up）；`settleCycle()` 用 `urgentDeferredSeq > outcome.stable.sourceCursor` 判断"延后的权威事实是否仍未折叠"，只有仍然未折叠时才把 follow-up 记为 `urgent`，否则保持 `trailing`（避免把普通尾巴误标成 urgent）；模块文档更新。
- **`basic/service.ts`**：观察者捕获 `filterEvent` 结果并计算 `authorityUrgency(...)`（只用投影 + 内存中的已提交指针），urgent 请求与 `maybeSchedule()` 一起在同一 microtask 上发出（B4.1 的四重围栏不变）；手动编辑路径把 `goalView`/`todoView`/`todoReferences` **原样带过**（人工编辑不是权威事实，不得发明或清空权威视图）。
- **`prompt/render.ts`**：注入顺序改为「头部 → 权威 Goal → 权威 TODO → continuation → 长列表/证据」；`cleared` 渲染为显式清除句；**当存在权威 Goal 视图时不再渲染 continuation 里的 `Current objective`**（避免陈旧/已清除叙事被当成生效目标）；不再渲染单独的 `TODO references:` 段（字段保留给客户端 UI）。

  - E06 `minEvents = 1`：写入与清空两波都 `trigger = urgent`，digest 由 `052b053b…` 变 `0698a7cb…`。
- **两处必须明说的装置模拟**（详见该目录 README §6）：harness 不挂载 provider，故 urgent 请求由 `requestUrgentLikeProduction()` 在同一 microtask 语义下补上；harness ledger 把 `trigger` 硬编码为 `'threshold'`，故真实 trigger 从 worker 自己的 `performBatch(trigger, window)` 调用点旁路记录。真 provider 的 durable audit / storage / 同步栈证据在 `tests/` 的两个新 spec。

## 6. 偏离与设计取舍（含未做项）

1. **未新增 `urgentDebounceMs` 之类配置**：`config.ts`、`package.json` 在本次允许范围之外。urgent 的合并策略是「**一个 microtask 批次**」：同一 tick 内观察到的多个权威事实由 `urgentThrough` + 单飞 `followUpRequested` 合并为一波，不以时间为窗。
2. **`changed` 含清空**：clear 也改变了已提交视图，因此同时出现在 `changed` 与 `cleared` 中；`cleared` 是"被清空"这一更精确的子集标记（指令文本已按此措辞）。测试对这一语义有显式断言。
3. **urgent 波的尾巴不升级为 urgent**：只有"延后的权威事实在本次提交后**仍在 cursor 之上**"时，follow-up 才记为 `urgent`；普通尾巴仍是 `trailing`（或低于阈值时等待），避免 audit 里的 trigger 名不副实。这是对 `settleCycle` 的一处语义收紧，已由"五值可区分"用例锁定。
4. **候选契约不再有 `todoReferences`**：引用改由 Host 从权威视图派生（最多 1 条）。旧模型输出里若仍带该字段，被 zod 非严格候选 schema 丢弃，因此模型无法回灌陈旧引用（敌意用例覆盖，含 `goalView`/`todoView` 伪字段）。
5. **注入层面的抑制范围**：仅抑制 **continuation 的 `Current objective`**（存在权威 Goal 视图时）。模型自己写进 `facts` 的文本里若提到旧 objective，仍会作为普通事实渲染——那属于"事实内容"而非"权威目标"，本轮不做事实级过滤。
6. **刻意保留的不变量**：`resolveAuthorityViews` 在窗口内**没有**权威事实时继承 base 视图（不是清空）；`todoReferencesOf()` 只在 `status = current` 时产出引用。
7. **明确不做**：B5 固定槽位注入与优先级/陈旧度标记（`R-P2-2`）、artifact parity（不重构建、不重打包）、B1 多实例写者仲裁、E05/E06 历史目录与共享 harness 的任何修改、`40/41` 号文档的任何修改。
8. **窗口/边界限制**：`todoReferencesOf()` 与视图 items 受 `maxEntryBytes`（2 000）与 `maxListItems`（8）约束；超限列表会被截断（Host 侧 bound），本轮不改变该上限。

## 7. 未解决 / 残留风险

2. **urgent 一次一 wave**：连续高频权威事实在极端情况下可能形成一串 urgent 波（每波都必须推进 cursor 才会继续）。当前用例证明"每 seq 只折叠一次、空尾巴不再发波"，但未做真实高并发压测。

## 8. 一句话交付结论

把 Goal 与 TODO 从"模型叙事的一部分"改成 **Host 拥有的权威命名视图**：窗口里最新的 `goal/change` / `todo/write` 决定提交态，替换是替换、清空是清空（空列表是合法事实而不是"空 payload"），并在观察到的同一 microtask 上请求一波 `urgent` 波次（每 seq 幂等、单飞、绝不在同步栈上做模型/存储工作），audit 行由此可区分 `startup/threshold/urgent/trailing/manual`；模型既看不到也写不进这两类视图，因此旧 Goal 与被清空的列表都无法从叙事里复活。E05/E06 的同 fixture 对照由 `reproduced`（缺陷）翻转为 `fixed`。
