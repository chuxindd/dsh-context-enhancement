## 2. 安全边界

所有实验必须满足：

1. 不使用真实 `$HOME/.dsh`；
2. 不读写用户现有 Session；
3. 不修改当前 Web profile 安装副本；
4. 不覆盖仓库现有 tgz；
5. 不占用 `127.0.0.1:8080`；
6. 不启动替代当前 GUI 的服务器；
7. 离线实验优先使用 fake LLM、fake TokenMeter 和临时 Session；
8. 真实进程实验使用独立 `DSH_HOME` 与独立端口；
9. 生成物只写入 `.experiment/` 和 `审计资料/实验结果/`；
10. 每个后台进程必须记录 job id 并在结束时回收；
11. 实验前后复算基线关键源码 hash；
12. 一旦检测到非实验目录的源码/config/lib 漂移，立即停止实验并报告。

## 3. 实验分层选型

固定采用三层实验，按顺序推进。

### L1：纯算法与 Session 回放

- 不启动 DSH Web；
- 使用 fake LLM、fake TokenMeter；
- 构造临时 Session events/surface；
- 直接调用公开或测试级内部入口；
- 目标是确定性验证分区、候选、replacement 和调度行为。

### L2：Stable Task State 服务级实验

- 使用真实 Session event 和 task-state service；
- 模型仍使用 fake LLM；
- storage 使用实验临时目录/backend；
- 验证触发、cursor、stable、注入、重启和 fork/resume。

### L3：隔离真实进程与多实例

- 使用临时 `DSH_HOME`；
- 两个受控 DSH 进程或最小 storage host；
- 使用 fake adapter 或离线 stub；
- 验证跨进程覆盖、CAS、缓存可见性和退出恢复；
- 最后执行，不能作为第一轮探索手段。

## 5. 固定实验清单

### E01：工具区预释放

**层级**：L1

**对应静态差异/事实**：工具维护调度、工具组候选、操作①/②互斥。

**构造**：

- `contextWindow=100000`；
- 总使用率位于 40%–70%；
- 工具压缩区放入多个满足摘要阈值的完整工具组；
- 近区保留当前完整 turn；
- fake LLM 返回严格缩减的结构化工具摘要。

**验证**：

- 40% 后是否触发工具维护；
- 候选是否仅来自工具区；
- 是否生成 tool-summary replacement；
- 操作②是否排除操作①成功结果；
- before/after total 与 surface 是否下降。

**判定**：工具区有合格候选却无 replacement，或候选越区、成功摘要又被裁剪，则 `reproduced`。

### E02：压力回落

**层级**：L1

**对应差异**：`IB-05/06/08/09/10`、遗忘矩阵 #3/#5/#7/#8/#9/#10。

**构造**：

- 初始总使用率 82%；
- 遗忘区包含至少三个 16K 左右安全批次；
- fake LLM 为每批生成约 1.5K 摘要。

**验证**：

- 当前实现选择 whole-zone 还是有界批次；
- `maxPressureBatches` 是否参与普通 pressure；
- 是否越过遗忘界；
- 维护后 U；
- stop reason；
- 每批净释放。

**理想判定基线**：有限批次、每批重测、不得越区、目标回落到 `pressureExitRatio=0.70`。

### E03：一工具一压缩抖动

**层级**：L1

**构造**：

```text
初始 82% pressure
→ 执行维护
→ 追加一个 3K–8K tool/result
→ 下一 pre-step
→ 重复至少 4 次
```

**记录**：

- maintenance 次数；
- 两次 maintenance 间工具调用数；
- 每次净释放；
- 维护后 headroom；
- no-progress/低收益路径。

**复现阈值**：连续至少三次维护之间都只有一个工具调用，且每次维护后 headroom 小于下一典型工具结果预算。

### E04：Step 边界盲区

**层级**：L1

**对应差异**：`IB-11`、遗忘矩阵 #12。

**构造**：

- `user/message` 不带 `data.turn/step`；
- 同一步包含 assistant/tool/result；
- forget/recent 边界故意落在该步骤内部。

**验证**：分区或批次终点是否切开用户请求与同一步响应/工具结果。

**判定**：安全检查返回可切，但结构事件证明仍在同一步，则 `design-confirmed`。

### E05：Goal 大幅更新

**层级**：L2

**对应差异**：无 urgent、无 Host goalView、模型自由 currentObjective。

**步骤**：

1. 创建 Goal A 并生成 stable；
2. edit 为语义完全不同的 Goal B；
3. 不再追加 19 个普通事件；
4. 检查 worker、stable 和下一次注入。

**记录**：Goal revision、stable revision、cursor、注入 objective、等待事件数。

**判定**：Goal B 不触发更新，且注入仍含 A，则 `reproduced`。

### E06：TODO 清空

**层级**：L2

**步骤**：

1. 写入多个 TODO 并生成 stable；
2. 执行合法 `todo_write({todos:[]})`；
3. 检查 filter 输出、pendingEligible、stable 与注入。

**判定**：空表投影为 null、cursor/stable 不推进且旧 TODO 仍注入，则 `design-confirmed`。

### E07：重启积压

**层级**：L2

**步骤**：

1. stable cursor=N；
2. 追加 cursor 后 eligible events，在更新前关闭；
3. 使用同实验 storage 恢复/resume；
4. 不追加新事件；
5. 等待超过 worker 正常调度时间。

**判定**：积压存在但无 startup wave，直到新 eligible event 才更新，则 `reproduced`。

### E08：Stable 注入累积

**层级**：L2

**步骤**：连续生成 20 个内容不同的 stable revision，每次完成一次 prompt assembly/step。

**统计**：

- task-state 注入消息总数；
- 当前 surface 可见节点数；
- 累计 token；
- 是否存在 replacement；
- token-meter 对注入的归因。

**判定**：可见或待后续压缩的旧快照随 revision 线性增长，则 `reproduced`。

### E09：Fork/Resume

**层级**：L2

**验证**：

- Resume 是否继续同一 stable；
- Fork 是否共享、丢失或重折父 stable；
- child 首批是否折叠继承前缀；
- lifecycle identity 是否区分 seeded child；
- `firstLiveSeq` 与 `inheritedEventCount` 是否被误用。

本实验允许得到 `inconclusive`，但必须保留完整 events 和 identity。

### E10：双实例

**层级**：L3

**前置**：E01–E09 完成；用户再次确认允许启动隔离进程。

**环境**：

- 同一个临时 `DSH_HOME`；
- 两个不同端口，均不为 8080；
- 独立测试 Session；
- fake adapter；
- 进程以托管 background job 启动。

**步骤**：

1. A、B 同时打开 storage domain；
2. A 写 Session A stable；
3. B 写 Session B stable；
4. A 再更新 Session A；
5. 关闭全部进程；
6. 重开只读检查介质。

**验证**：记录丢失、revision 分叉、外部变更不可见、告警/冲突行为。

**安全判定**：任何命令将访问真实 home 或 8080 时立即停止。

## 8. 实验产物与源码修改的隔离

第一阶段实验 harness 可以新增测试/fixture，但必须先形成文件级实施计划并获确认。默认不修改生产源码。

若为观测必须增加 diagnostics：

1. 先在审计文档记录缺失字段；
2. diagnostics 必须默认关闭；
3. 输出到实验目录；
4. 不改变调度、候选或提交逻辑；
5. 用测试证明开关关闭时行为不变；
6. 实验后由审计决定是否保留为正式可观测能力。

## 9. 实验后的改进流程

每轮实验完成后按固定顺序处理：

```text
实验结果落库
→ 主代理核对静态差异 ID 与动态证据
→ 更新差异矩阵置信度
→ 形成最小改进批次
→ 写文件级 PLAN、迁移和测试
→ 用户确认
→ 实施
→ 重跑对应实验与回归
```

禁止看到一个失败实验就直接在生产源码打补丁。

改进优先级：

1. 数据损坏/跨实例覆盖/错误权威状态；
2. 压力释放失效和目标更新不生效；
3. 恢复、注入累积和 provenance；
4. 可观测性、配置债和文档。
