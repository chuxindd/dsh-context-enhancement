## 接受的证据

1. DSH storage domain 的 `KvTable.put` 没有 expected revision/CAS；
2. `update` 只保证单进程写链，不保证跨进程；
3. JSON 单文档写入没有跨进程锁或 writer lease；
4. 已打开 domain/table 没有 refresh/reload；
5. 插件边界没有 JSON root/介质身份，不能安全实现同介质跨进程锁；
6. SQLite 路径也没有当前需要的 CAS 条件；
7. DSH 上游文档已把跨进程 revision pattern 列为未落地能力；
8. 现有 fail-closed 能处理 version-mismatch/invalid-record，但不能解决多实例写竞争。

## 不接受的伪修复

以下方案不算 B1 修复，后续不得提交：

- 进程内 mutex；
- 时间戳或随机 token 代替 revision compare；
- “先读内存再写”代替 refresh/CAS；
- 插件配置一个锁路径但不保证两实例使用同一介质；
- 只把 layout 改成 per-record 就宣称解决同 revision 分叉和 stale view。
