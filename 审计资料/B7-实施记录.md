## 0. 前置：产品语义选择（写代码之前固定，不允许两种混合）

PLAN §9 要求在两种语义中**选定一种**，未选定前不得修改 cursor 语义。本批次选定：

### 选定：**语义 A —— child 从 own-events boundary 独立重建**

契约文本（本批次以此为准，也是全部断言的对照物）：

1. **继承边界是 header 的 durable 事实。** 一个 `header.isSeeded === true` 的 Session（fork child / seeded restore）拥有继承前缀 `[0, inheritedEventCount)`；边界只取 `Session.inheritedEventCount`，**永不**取 `firstLiveSeq`（后者是"本进程构造 seed 长度"的 in-process 事实）。
2. **child 的 own-events 起点就是它的 cursor 起点。** 在 child 自己没有任何 committed 记录时，有效 cursor 起点为 `inheritedEventCount - 1`（不是 `-1`）：child 的第一批窗口**从自己的事件开始**，继承前缀**不重复折叠**为 child 的 live 事实。
3. **child 独立形成自己的 revision 1。** child 的 stable 是自己的（自己的 base 为 `null`、自己的 Host-minted entry id、自己的 digest、自己的 cursor ≥ 边界），不读取父 Session 的记录、不把父 stable 当作自己的已提交版本。
4. **边界可读。** child 的 committed stable 与 open audit 行携带 `inherited` 标记（`source` + 覆盖范围 `ownBoundarySeq`/`inheritedThroughSeq`），因此"哪些是被继承的、哪些是本 lifecycle 的 live 事实"无需靠 `cursor = -1` 隐式推断。
5. **fail closed。** 若一个已存记录覆盖声明落在 live 边界之内（`sourceCursor < ownBoundarySeq`），或它的 `inherited` 标记与 live 边界不一致，则该**覆盖声明被拒绝**：有效 cursor 被抬到 live 边界（`ownBoundarySeq - 1`），绝不因此折叠继承前缀；记录里的 stable **内容**仍然照常服务（它是本 lifecycle 自己的已提交内容），只是它的覆盖范围不再被采信。
6. **归属不跨越 lifecycle。** parent 与 child 的 instance cursor、slot 记录、terminal verdict、audit 行各自属于各自的 lifecycle；child 不读父的 in-memory 指针，父的记录不被 child 改动。
7. **未选**：语义 B（child 接受一次父 stable bootstrap 并记录 `inherited` 来源与覆盖范围）。理由见 §2.3；`审计资料/42` §9 的"验收只证明选定契约一致，不把未选另一方案写成失败"照此执行。

### 2.3 为什么选 A 而不是 B（B 在"单实例 + 当前 API + 无上游改动"下不可证明）

- 语义 B 需要 child 拿到**父 Session 的 committed stable**。当前 API 下唯一结构化来源是 storage 的 `sessions` 表（按 SessionId 键），而父记录的 lifecycle 只由 `(createdAt, cwd)` 围栏（本批次**不改**这一步，见 §3.5）：
  - 若父 Session 在本进程内 live，可用 `ctx.sessions.get(parentSession)` 得到其 `createdAt/cwd` 作见证 —— 这只覆盖"fork 时父还活着"的情形；
  - child 被 resume 时父通常**不在场**，此时 child 自己 durable 的字段里只有 `parentSession`（id），**没有**父的 `createdAt`。要让它可证明，只能 (a) 把 prompt 消费者写的 slot 节点（`source.lifecycleCreatedAt`）当作父 lifecycle 见证 —— 那是把 provider 与另一个消费者的产物耦合起来，且父从未提交过 stable 时根本不存在；或 (b) 在记录里新增一个"父 lifecycle 见证"字段，而该字段无法由 child 自己的前缀验证。
  - 结论：B 的契约会在"fork 时"与"resume 时"行为不一致（可 bootstrap / 不可 bootstrap），不是一个可固定的契约。
- 语义 B 还会把父的 Host-minted entry id 带进 child 的 stable（模型 echo 父 id 才能得到相同内容），即 **entry id 所有权跨 lifecycle 共享**，与本批次覆盖项 4 的"child 不得复用 parent 归属"直接冲突；要避免就必须在 bootstrap 时重铸全部 entry id —— 那是"bootstrap 传输 + 重新识别"，远超"接受一次父 stable"。
- A 只需要 `inheritedEventCount`（事实 1、4）与 JSONL 的 `seedLength`（事实 5），单实例可完整证明，且**继承前缀不重复折叠**是它的定义性质。
- 未选 B **不记为失败**：PLAN §9 明确"验收只证明选定契约一致"。
