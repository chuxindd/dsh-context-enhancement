### 1.1 `src/compaction-basic.ts` 逐处改动

1. **`PressureStopReason` 新增 `'batch-limit'`**（行 101）。语义：**本次 invoke 的批次预算耗尽且仍高于 exit line**。
   它是“pass 级别”的终止原因，**不是**任何单批次的收益判定，因此不得再被写成 `'low-yield'`。
2. **pressure loop 的终止判据改为 exit line**：
   - `if (measurement.totalTokens <= exitTokens)` → `pressure-exit`（原为 `< exitTokens`；“落在目标线上”即“达标”）。
   - **删除** `if (measurement.totalTokens < spec.thresholdTokens) { finishLedger(null, …); return }` 这一提前返回。
     这是本次最关键的语义修正：exit line 由配置保证**严格低于** trigger，因此“只压到 trigger 以下”必然仍高于 exit line；
     在 trigger 处收手等于**把有界批次循环静默退回单批**，并使 exit target 永远不可达 —— 正是 E03 记录的 6/6 次压力维护在 78%–79% 退出、
     余量不足一个典型 tool result、导致每次工具调用重触发维护的成因。循环现在按 exit line 继续迭代。
3. **低收益严格化**：`netReleaseTokens < minNetReleaseTokens && netReleaseRatio < minNetReleaseRatio`（**两者都未达标**）
   才写 `low-yield`；写入后**立即结束本次付费 pass**（删除原“更宽跨度可再试一次”的 `lowYieldSpanTokens` 重试分支），
   不再在同一压力状态下继续付费。已提交的 replacement 无法回滚，所以账本如实记录该批次，而不是假装它没发生。
4. **批次预算终止的 typed 判定**：循环走完 `maxPressureBatches` 后，
   - 已到 exit line → `finishLedger('pressure-exit', true)`；
   - 仍高于 exit line → 保留既有 `ctx.logger.warn('… ended after N batch(es) … > exit …')`，并
     `finishLedger('batch-limit', false)`（**替换**原先的 `finishLedger(… ? 'low-yield' : null, …)` 误标注）。
     该路径**不**调用 `logPressureStop`：批次预算耗尽不是“无法继续”的 veto 原因（既有 warn + 账本 typed verdict 已足够），
     且调用它会击中 `compaction-pressure-reentry.spec.ts` harness 缺失的 seam（见 §1.2），产生与本任务无关的连带失败。
5. **seam 崩溃修复 A（账本存储）**：新增模块级 `fallbackPressureLedgers` 与 `pressureLedgerStore(store)`；
   `this.pressureLedgers.set/get` → `pressureLedgerStore(this.pressureLedgers).set/get`。
   真实 engine 仍用**自己**的 WeakMap（两实例不共享）；只有“借用 prototype 方法的裸 seam 对象”落回模块级存储，
   **诊断写入永不把一次压力维护变成 runtime error**。`pressureLedger()` 已由 B3.1 spec 用 `prototype.pressureLedger.call(fake, …)` 调用，行为不变。
6. **seam 崩溃修复 B（reentry 判定纯函数化）**：`private pressureReentryVerdict(...)` 原样搬成**模块级纯函数**
   `pressureReentryVerdict(session, sources, blockerSeq, measurement)`，调用点去掉 `this.`。
   函数体**逐字未改**，不涉及任何 reentry/same-pass 语义变更；改动原因与 5 同类：它是 B3 新增的方法，
   envelope-budget / reentry-liveness / 三个 spec 的裸 seam 对象不含它，会以 `TypeError` 打断整条回归面。
7. **注释与文档同步**：更新 `compactIfNeeded` 的循环说明（exit line 为终止判据、`pressure-exit`/`batch-limit`/`low-yield` 三者的区别）、
   `PressurePassLedger.stopReasons` 文档、`TERMINAL_PRESSURE_REASONS` 文档（`batch-limit` 与 `low-yield` 同理**非**终态）。

**未改动**：`maxPressureBatches` 的 schema/默认值/`compactionRetries` 别名映射、`pressureExitRatio`/`minNetRelease*` 的解析与校验、
`reclaimTokens = max(0, total − exitTokens)`（B3 已落地的 exit 目标口径）、fixture token 口径、`Bcap`/`G`/保留尾部/工具档治理。

## 2. B3.1 语义（本轮定稿）

1. `exitTokens = min(thresholdTokens, floor(W × pressureExitRatio))`；压力 pass **以 exit line 为唯一成功判据**：
   维护后 `totalTokens <= exitTokens` 才算 `exitReached`。
2. 循环：`while (batch < maxPressureBatches)`，**每轮重新 `measure()` → 重新 `zones()` → 重新两个 envelope budget → 重新 `planPressureSpan`**（原实现已如此，本轮不再被 trigger 判据提前打断）。
3. 终止并返回 typed 原因：`pressure-exit`（已达标）/ `batch-limit`（批次预算耗尽且仍高于 exit line）/
   `low-yield`（某批次**同时**未达两条净释放下限，且**立即停止付费**）/ `no-progress`（总压力未下降，memoized terminal）/
   plan veto（`envelope-dominated`、`span-below-minimum`、`no-safe-prefix`、`reentry-deferred`、`tool-stage-deferred`、`same-pass-tool-replacement`）。
4. `PressurePassLedger` 逐批如实记录 `spanTokens / beforeTokens / afterTokens / netReleaseTokens / netReleaseRatio / reasons`，
   包括**净释放为 0** 的批次（不隐藏），并记录 `exitReached`、`terminalReason`、`stopReasons`。

### 2.1 两处 fixture 几何事实（本轮断言修正的唯一依据）

`tests/compaction-pressure-low-yield.spec.ts` fixture：contextWindow 10000、10 个各 1000 token 的 surface 节点（request/header 不在 surface 上）、
threshold 8000、`pressureExitTokens` 7000、`Rkeep` 2000、`Bcap` ≈ 7049、`maxPressureBatches` 2。
⇒ `reclaim = 10000 − 7000 = 3000`，deficit-sized 前缀 = 索引 0..3 = **4000 token**。

- 原本 test 1 声称“4900 字符 = 1225 token 的 checkpoint 释放 2775，落在**正好 7000**”：
  实际 `10000 − 2775 = **7225**`，**一个 4000-token 跨度的单批不可能达到 7000**（需要 ≥ 5225 token 的跨度才够）。
  这就是任务书说的“伪造精确值”。
- 第二批（两个用例几何完全相同，仅 checkpoint 价格不同）重新规划后：head 只剩第一批刚落下的 checkpoint，
  规划器恒从 head 起算（E02 契约 `startIndex = 0`），因此第二批的 deficit-sized 前缀就是该 checkpoint 本身，
  再摘要一次释放 0 token → 由 memoized `no-progress` 终止。**注意：普通 pressure 不再是单批（`batchesRun = 2`），
  但要让第二批次付在“新内容”上，需要后续批次从 head checkpoint 之后开跨度 —— 那是 B3.2 的 reentry/same-pass 工作（本轮禁改）。**
