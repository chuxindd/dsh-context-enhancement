## 1. 证据等级定义与标注规则

本矩阵只用以下四级 verdict 词，并强制附加环境标注。判定词取自 `审计资料/32-运行时复现实验方案.md:419` 的固定词表。

| 等级 | 定义 | 必须具备的证据形态 |
|---|---|---|
| `reproduced` | 在指定环境中，按**实验前固定**的判据观测到了与待验证问题一致的行为 | 结构化账本 + 原始 runner 输出 + 前/后基线哈希核对 |
| `design-confirmed` | 只有静态设计/源码证据，或动态只证明“当前实现的判定行为与设计一致”，**未证明用户可见影响** | 源码路径引证 + （若有）结构断言 |
| `not-reproduced` | 在指定路径下按实验前固定判据**未**观测到该问题 | 判据清单 + 逐条 false 记录。**不等于“无问题”**，只表示该判据未被触发 |
| `inconclusive` | fixture/runner/介质无法产出证据（不为通过而伪造） | 失败/阻塞原因记录 |

强制环境标注（写在等级后括号内）：

- `受控`（controlled）：fake LLM / fake TokenMeter / 临时 Session 或同进程顺序挂载的临时 Context，**不是**独立 OS 进程。
- `真实进程`（real-process）：独立 OS 进程（须给出 pid/启动时间/退出码）。
- `真实持久介质`（real-medium）：真实 `dsh-storage` 域 / 真实 JSONL Session 持久化与 dispose-reopen。
- `阶段评审级`（review-only）：结论只存在于阶段评审文档，缺少该实验的 `result.json`，可复算性弱于其余各项。
