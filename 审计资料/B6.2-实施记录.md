## 2. 实现设计

### 2.1 状态机与转移（`src/internal/compaction/tool-group-audit.ts`）

| 状态 | 含义 | 谁能写 |
| --- | --- | --- |
| `open` | 尝试在飞行中，属于开启它的实例 | `openToolGroupAudit` / 采纳（`adoptToolGroupAudit`）/ 恢复自己的行（`resumeToolGroupAudit`） |
| `success` | **尝试自己**提交的已落地归约 | `finishToolGroupAudit(record,'success')`（仅由 `open` 出发） |
| `fallback` | 本次尝试被确定性拒绝（route/empty/json/schema/source 等） | 同上，`transient=false` |
| `failure` | 本次尝试可重试失败（stream/failure） | 同上，`transient=true` |
| `aborted` | **later 观测**的裁决：没有任何证据证明落地（进程中断，或无法与并发写者区分的他人 `open` 行） | 只有 `abortToolGroupAudit`（经 `planAuditRecovery`） |
| `repaired` | **later 观测**的裁决：Session provenance 证明本组落地 | 只有 `repairToolGroupAudit`（**空证据抛错**） |

关键不变量：

1. **`aborted` 永远不被读作已提交**：`isServedAudit('aborted') = false`，故 `servedReplacementSeqs` 不含它，B6.1 的分类围栏不会被它触发；
2. **`repaired` 不能提升类型**：证据只能来自 `sessionLandedReductions(index, fingerprint)`，即当前 surface 上**校验通过**的 provenance，且 `kind==='tool-summary'` 且 `groupId===fingerprint`；`repaired` 只把这件事**记回**audit，不改变任何节点的 kind；
3. **采纳就地（in place）**：一个组只保留一行；`adoptToolGroupAudit` 把 `attempt+1`、清空 `replacementSeqs`/`repairEvidence`/`error`/`diagnostic`，并记录 `recoveredFrom`，因此持久 attempt 预算不会被重复计数（否则重启一次就会提前耗尽配额）；
4. **恢复不重复写**：`planAuditRecovery` 对"已经是该裁决"的行不再产生步骤。

### 2.2 诊断码（稳定字符串，可断言、可 grep）

| 码 | 触发 |
| --- | --- |
| `interrupted-attempt` | 非本实例的 `open` 行被判 `aborted` |
| `adopted-interrupted-attempt` | 该行被就地采纳为新一次尝试 |
| `session-evidence-served` | Session provenance 证明落地 → `repaired` |
| `landing-claim-conflict` | 行上的认领与 Session 日志不符 → `aborted`（认领被撤回，但作为取证字段保留） |
| `attempts-exhausted` | 该组持久/降级配额用尽，拒绝再做模型工作 |
| `audit-write-failed` | 持久 audit 写入被拒（归约仍按 Session 日志分类） |
| `audit-record-missing` | 目标行已不在（`missing-key`，即整篇文档被他人覆盖的可观测症状） |
| `audit-landing-unrecorded` | Session 证明落地、而 audit **没有任何行**记录该组（文档被删除/覆盖/损坏） |

### 2.3 领域契约（`tool-group-domain.ts`）

- `status` 枚举扩为 `open|success|fallback|failure|aborted|repaired`；
- 新增**可选**字段：`attempt`、`ownerId`、`recoveredFrom`、`diagnostic`、`repairEvidence`；
- **域版本保持 1（刻意）**：`single` 布局按精确版本读取，升版会让**所有既有文档**在 open 阶段 `version-mismatch` 被拒，从而把 audit 整体关停——比缺陷本身更糟。新字段全部可选 ⇒ 老文档仍通过 `.strict()` 校验（已由"损坏文档"用例的第三类反证：只有被改成 version 9 的文档才会被拒，且拒绝理由为 `stored version 9 != expected 1`）。

### 2.4 存储层（`tool-group-audit-store.ts`）

- `TOOL_GROUP_AUDIT_WRITE_ATTEMPTS = 2`：`open`/`finish` 都走 `withAuditWriteRetry`；
- `isRetryableAuditWrite`：`DomainError('closed')`（域已关闭）与 `DomainError('missing-key')`（行已不在，重试不可能成功）**不重试**，其余（I/O、忙等）重试一次；
- 写入仍是**无条件写**（上游无 CAS）：这是可用性重试，**不是**冲突检测，注释里如实写明；
- 接口 `ToolGroupAuditStore` 未变 ⇒ 既有 fake store 与既有测试无需改动。

### 2.5 引擎接线（`src/compaction-basic.ts`）

1. **恢复先于调度**：`compactIfNeeded`（行 866）与 `summarizeToolGroups`（行 1778）在**任何工具工作被规划之前**调用 `recoverToolGroupAudits(this, session)`；每引擎每 session 只判一次（`WeakSet`），裁决写入失败会带 `missing-key` 症状上报（行 312–335）。
2. **模型调用前先落尝试行**：`attemptSlotFor` 决定"续用自己 `open` 的行 / 就地采纳他人行 / 新开一行"，`store.open(open)` 在模型调用**之前**；被拒时进入显式降级模式（`auditWrites=false`），并计入内存 `unwritten` 账本（行 1792–1849）。
3. **归约不因 audit 失败而丢失**：已落地后跳过 success 提交，只记诊断（"the landed reduction keeps its durable Session provenance"），绝不把已落地归约降级成终态失败（行 1915–1923）；`commitToolGroupSuccess` 仍保留"成功提交"的重试与兜底（既有测试断言其告警文案，未改）。
4. **调度判定以 Session 为准**：`mayAttemptToolGroupSummary`（行 354）先看 Session 证据（`landed.length > 0` ⇒ 不欠工作），再看内存降级账本，再看持久预算（`hasToolGroupAttemptBudget`）；两个调度探针（行 1461、1501）与 `summarizeToolGroups`（行 1803）共用它。
5. **丢失被显式上报**：`sourceIndex`（行 1390–1398）在构建索引时调用 `reportUnrecordedAuditLandings`（行 406）：凡是 Session 证明为 `tool-summary` 而其 `groupId` 在 audit 中**无任何行**，上报一次 `audit-landing-unrecorded`。这是"audit 丢失"唯一可达且不产生噪音的观测点（放在选择结果上空转的调度分支里将永远不可达，本批次据此调整了实现位置）。
6. **性能/健壮性**：所有 audit 记账都在模块级 `WeakMap<object, AuditEngineState>` 中按**接收者**存放（`owner`/`recovered`/`unwritten`/`logged`），因此既有"把生产方法借到裸对象字面量上跑"的测试写法不会因类字段为 `undefined` 而崩（这是本批次实测踩到并修正的一处）。

## 7. 行为变更与已知影响（诚实披露）

1. **`open` 行不再可能被"永远当作在进行中"**：重启后它被判 `aborted`，因此**同一个组可以被重启后的实例再次尝试**（`attempt+1`，持久预算内）。相对 B6.2 之前"`open` 行永久挡住该组"的行为，这是有意的修复；代价是**一次中断会消耗一次尝试配额**（`TOOL_GROUP_AUDIT_MAX_ATTEMPTS = 2`），即"模型一直失败 + 反复重启"的组会更快耗尽配额——这是把不可判定的中断换成有界重试的显式取舍。
2. **坏审计不再能永久卡死一个组**：认领与日志冲突的行被判 `aborted`（认领撤回）。此前它的"认领"会让 `shouldAttempt` 恒为 false（`inert`），使该组既不被摘要也不被压力层回收；现在恢复裁决后它重新变为 `actionable`。分类侧行为**不变**：冲突期间节点仍 fail closed 为 `unknown-replacement`（B6.1 规则），撤回后回到 Session 真相。
3. **audit 写入被拒不再取消归约**：此前 `open` 写入失败会跳过整次尝试（连模型调用都不做，也无法分类落地结果）；现在模型调用与归约照常，只是 audit 记账缺失，并有用内存账本限制"审计一直坏"时的模型花费（每引擎每 fingerprint 2 次，成功写入后清除）。
4. **新增 5 个可选字段 + 2 个状态**：老文档（无这些字段、状态属于旧五态）仍按 `.strict()` 通过与解析，**域版本保持 1**；因此不会出现"升级即整域拒绝"。
5. **未改变**：B6.1 的 provenance 契约与分类权威、官方 `compaction/prune` 字段与 invariant、surface replacement 契约、`tool-result-pruner` 的裁剪语义、shadow-price 定价与折叠、task-state 语义与存储、`ToolGroupAuditStore` 接口。
6. **clean break（沿用 B6.1，未加重）**：B6.1 之前的旧 replacement 依然 `unknown-replacement`。本批次**未**做旧数据回填（回填需要更多证据来源，不属于"用 Session provenance 修复调度"的范围）。
